# 사용된 컴퓨터 지식/스킬 — 인천대 알림 모음

## 프로젝트 요약

인천대 여러 사이트(홈페이지 공지, 데이터과학과, 도서관, 기숙사 등)의 공지를 자동으로 모아 보여주는 웹페이지를 만들었다. 매일 자동 수집·배포되며, 읽음/즐겨찾기/탭 구분, 스와이프, 모바일 디자인 등 기능을 계속 추가했다. 자세한 진행 과정과 시행착오는 이 프로젝트의 `README.md` 참고.

## 사용한 지식/스킬

- CSV 파일(표 데이터를 담는 단순 텍스트 파일): 사이트 목록(`input/sites.csv`)을 코드 밖에서 관리해 추가/삭제 시 코드 수정이 불필요해짐.
- 웹 스크래핑(requests+BeautifulSoup): 게시판 페이지를 받아와 제목·날짜 등 필요한 부분만 자동으로 골라냄.
- 정규표현식(regex): 제목·부서명에서 학과 이름 패턴을 찾아 관련 공지를 자동 분류.
- 수집/화면 생성 분리(collect.py / build_site.py): 디자인만 바꿀 땐 재수집 없이 build만 다시 실행하면 됨.
- GitHub Actions: 매일 정해진 시각에 자동으로 수집→생성→커밋·푸시 실행(cron 시각은 UTC라 9시간 빼서 계산).
- GitHub Pages: 저장소의 `docs/` 폴더를 무료로 공개 웹사이트로 배포(`.nojekyll` 파일 필요).
- cron-job.org(외부 스케줄러): GitHub Actions 예약 실행이 며칠씩 안 도는 문제를 겪은 뒤, 매일 정해진 시각에 대신 실행 버튼을 눌러주는 외부 서비스로 보강함.
- 페이지네이션 자동 넘기기: URL의 페이지 번호를 코드로 바꿔가며 여러 페이지를 순회.
- 증분 수집("이미 아는 글" 기준): 날짜 대신 저장된 링크 목록과 비교해 새 글만 골라내 누락을 줄임.
- 제목 속 기간 읽어내기(regex 날짜): "~7/24"류 표현에서 마감일을 뽑아 마감 전 공지까지 포함시킴.
- localStorage: 서버 없는 정적 사이트에서 "읽음" 표시를 브라우저에 저장(기기 간 동기화는 안 됨).
- 탭 UI(자바스크립트): 안읽음/읽음/즐겨찾기/타학과 4개 탭을 조건 계산으로 보이고 숨김.
- jsdom(가짜 브라우저): 버튼 클릭 등 실제 동작을 코드로 재현해 눈으로 안 보이는 버그를 찾아냄(단, 실제 화면 렌더링까지는 확인 못 함).
- 반응형 디자인 + CSS 변수: 모바일 화면을 기준으로 레이아웃을 짜고 색상은 변수로 통일 관리.
- Google Fonts: CSS `@import`로 외부 폰트를 불러옴(오프라인이면 기본 폰트로 자동 대체).
- data-* 속성 활용: 진짜 링크가 없는 사이트에서 속성값을 조합해 실제 글 주소를 직접 만들어냄.
- 중복 제거(seen_links 집합): 페이지마다 반복되는 상단 고정 글을 한 번만 저장하도록 걸러냄.
- 리스트 병합·정렬: 여러 사이트 공지를 하나로 합쳐 날짜 문자열 기준으로 최신순 정렬.
- Base64 디코딩: 암호처럼 보이는 URL을 풀어 그 안에 숨은 진짜 게시판 주소를 찾아냄.
- Playwright 네트워크 관찰: 자바스크립트로 그려지는 사이트에서 실제 데이터가 오는 API 주소를 찾아냄(찾은 뒤엔 requests만으로 충분).
- 게시판 중복 여부 확인: 글 번호는 두고 게시판 번호만 바꿔 같은 글이 열리는지 교차 확인.
- 바로가기 알림 트릭: 로그인이 필요해 못 긁는 사이트는 링크 끝에 날짜를 붙여 매번 "새 글"처럼 보이게 함.
- Pointer Events(스와이프): 터치·마우스를 하나의 이벤트로 처리해 카드를 밀면 읽음 처리되게 함.
- Set의 저장 순서 + CSS order: 새 데이터 없이 기존 저장 순서를 활용해 "최근 읽은 순" 정렬을 구현.
- HTML hidden 속성: 복잡한 모달 없이 속성 하나로 펼치기/접기 구현.
- HTML `<details>/<summary>`: 자바스크립트 없이 "한 번 더 클릭하면 펼쳐지는" 2단계 접이식 목록(출처 패널의 에타/캠퍼스픽 그룹) 구현. 이름 접두사("에타 ", "캠퍼스픽 ")로 자동 그룹핑해서, 사이트를 추가/삭제해도 그룹핑 코드를 따로 안 건드려도 됨.
- 기존 데이터 재사용: `data.json`에 이미 있는 사이트 정보를 그대로 읽어 "출처" 목록을 자동 생성.
- 새 사이트가 로그인 필요 여부와 무관하게, `curl`로 먼저 접속해보고 목록이 서버에서 바로 그려져 나오는지 확인하는 습관: 캠퍼스픽은 로그인 없이 되고 목록도 HTML에 그대로 있었지만(에브리타임과 다름) 날짜 정보가 없어서 일단 바로가기 카드로 추가함.
- 데이터가 계속 쌓이는 시스템에서 "개수 제한"과 "날짜 기준 만료"는 서로 다른 문제를 푼다는 걸 배웠다: 개수 제한(300건)은 무한정 커지는 것만 막아줄 뿐, 뜸한 게시판의 몇 년 전 글은 그대로 남고 잦은 게시판의 최근 글은 오히려 밀려날 수 있다. "올라온 지 90일 지나면 제거"를 추가로 넣어서 실제 관련성 기준으로 정리되게 했다. 이때 이미 있던 "제목의 기간이 아직 유효하면 오래된 글도 남긴다"는 기존 로직과 새 90일 규칙이 충돌할 뻔했는데(단순히 날짜만 보면 학기 내내 걸어두는 공지를 지워버림), 새 규칙 안에 기존 함수(`period_still_relevant`)를 그대로 재사용해서 예외 처리를 끼워 넣는 방식으로 합쳤다 — 새 요구사항을 구현하기 전에 비슷한 기존 로직이 있는지 먼저 찾아보고 충돌 여부를 확인하는 습관이 중요했다.
- localStorage로만 관리되는 상태(즐겨찾기 등)는 서버 쪽 데이터 정리 로직이 그 존재를 알 수 없다는 한계를 사용자에게 명확히 알렸다: 90일 지난 공지를 서버(data.json)에서 지우면, 그걸 즐겨찾기 해둔 사용자의 브라우저에서도 그냥 화면에서 사라진다(주요 공지 탭 포함). 이런 트레이드오프는 구현 전에 먼저 사용자에게 설명하고 선택하게 하는 게 나중에 "왜 즐겨찾기한 게 없어졌지?"라는 혼란을 막아준다.

## 다음에 비슷한 작업을 할 때 해야 할 점

- 같은 사이트에 새 게시판을 추가하기 전, 글 번호를 유지한 채 게시판 번호만 바꿔서 "카테고리 필터"인지 먼저 확인한다.
- requests로 내용이 비어 보이면 바로 포기하지 말고 Playwright로 실제 데이터가 오는 API 주소부터 찾는다.
- 같은 CMS 템플릿을 쓰는 사이트면 새 파서 없이 기존 파서를 그대로 재사용할 수 있다.
- "자동으로 커밋·푸시하는" 프로젝트를 로컬에서 다시 실행하기 전에는 `git fetch`로 원격이 앞서 있지 않은지 먼저 확인한다.
- 여러 서비스가 함께 쓰게 될 수 있는 파일은 처음부터 특정 서비스 이름(`everytime_reminders.csv`)이 아니라 역할 이름(`shortcut_reminders.csv`)으로 짓는다.

## 다음에 비슷한 작업을 할 때 주의할 점

- 시작할 때 일부 페이지만 채운 사이트는 증분 수집이 옛 글을 전부 새 글로 오인해 폭주할 수 있다(실제로 10건→150건 사고 발생).
- 스와이프 등 터치 동작과 jsdom 테스트 결과는 실제 휴대폰에서 다르게 동작할 수 있어 실기기 확인이 꼭 필요하다.
- GitHub Actions 서버(클라우드 IP)는 학교 사이트에서 접속이 막혀 로컬과 다르게 타임아웃 날 수 있다. 자주 안 바뀌는 사이트라면 포기하고 빼는 것도 합리적 선택이다.
- 화면에 잠깐이라도 노출된 API 토큰/비밀번호는 위험도와 무관하게 폐기 후 재발급한다.
- GitHub 저장소 생성과 Pages 활성화는 사람이 브라우저에서 직접 클릭해야 하는 수동 단계다.
